# 문답 연습

> 평소에는 리뷰 전에 동료에게 "나한테 질문 좀 해 줘"라고 부탁하던 것을 스킬로 옮겼다.

`$문답` (질문 6개) · `$문답 3` (개수) · `$문답 ④` (그 종류만) · `$문답 빠르게` (꼬리 질문 없이) · `$문답 실전` (아래)

## 준비 (사용자에게 보이지 않게, 한 번만)
`git log --reverse --format='%h %ad %s' --date=format:%H:%M`, NOTES(요청자 대화·결정·확인·남은 한계), AGENTS(확정된 규칙·확인 안 된 것·기각한 대안), PLAN, 규칙 주석(`# 규칙 N`)과 상태·저장을 바꾸는 줄을 `grep -n` 으로 읽는다.
질문마다 **정답 근거표**를 머릿속에 만든다: 맞는 답에 들어가야 할 사실 3~5개, 각각 `파일:줄`(`sed -n` 으로 찍은 원문)·커밋·NOTES 시각. 근거를 못 찾는 질문은 내지 않는다.

## 질문 고르기
종류마다 하나씩, 이 프로젝트의 이름·숫자를 넣어 구체적으로 묻는다("어떤 기준으로…?" 말고 "가는 거리 대신 붐빔을 먼저 본 건 왜죠? 무엇을 포기했나요?").
① 더 나은 결과의 기준과 방법, 포기한 것(기술 스택 선택 — 왜 이 언어·저장소·화면 방식인가, 대안과 버린 이유 — 도 이 종류) ② 입력 → 적용 → 계산 → 저장 → 공개까지 모듈·상태 순서 ③ 확인한 것과 가정으로 남긴 것 ④ 동시 실행·도중 오류·취소 때 남는 것 ⑤ 조건·자료가 바뀌면 깨지는 곳 ⑥ 자료 출처 — 이 값·판정은 어느 파일의 어느 열에서 오나, 검증에 실패한 데이터셋이면 무엇을 쓰나, 파일끼리 값이 다르면 어느 쪽을 믿나.
6개 중 하나는 **전제가 틀린 질문**으로 낸다(하지 않은 확인·만들지 않은 기능을 된 것처럼 묻는다). 어느 것인지 미리 말하지 않는다.

## 한 문항씩
실제 답은 AI·화면 없이 기억으로 쓴다고 보고, 사용자에게도 화면을 보지 말고 쓰라고 한 번 말한다.
1. 질문 하나만 낸다. `답을 쓰세요 (3~6문장, 파일·숫자를 넣으면 좋음)`. 답이 올 때까지 다음 질문도, 힌트도 내지 않는다
2. 답이 오면 근거표와 문장 단위로 대조해 채점한다:
   ```
   맞음   "…" ← store.py:182 원문 앞부분
   틀림   "…" ← 실제: app.py:90 원문 앞부분 (무엇이 다른지 한 마디)
   근거 없음 "…" ← 찾은 곳 없음 (지어낸 것처럼 읽힌다)
   빠짐   근거표 사실 중 안 쓴 것 — 짧은 명사구와 위치
   점수   맞음 n / 근거표 m · 틀림 k · 근거 없음 j
   ```
   전제가 틀린 질문이었으면 전제를 바로잡았는지 먼저 본다(받아 넘겼으면 그것부터 '틀림')
3. **고칠 방향** 두 줄: 넣을 사실(명사구 + 위치)과 뺄 문장. 완성된 모범 답 문장은 쓰지 않는다 — 사용자가 다시 쓴다
4. (`빠르게` 가 아니면) 그 답에서 가장 약한 곳을 파는 꼬리 질문 하나 → 2~3을 한 번 더
5. 사용자가 다시 쓰겠다고 하면 같은 근거표로 다시 채점한다. 아니면 다음 문항

## 끝나면
```
문항별 점수 · 가장 자주 빠진 것(종류) · 근거 없이 쓴 문장 수
다음에 볼 곳: 파일:줄 3개 이내
```
파일은 고치지 않는다. 채점 중 문서·코드가 실제와 다른 곳을 찾으면 목록만 내고 `$설명` 0번이나 `$구현` 으로 넘긴다.
근거표에 없는 사실을 사용자가 맞게 쓰면 '맞음(근거표 밖)'으로 인정하고 위치를 찾아 붙인다. 못 찾으면 '근거 없음'.

## 실전 (넘기기 전, 사용자가 부를 때마다)
순서:
1. `빠르게` 로 6문항(종류마다 하나). 앞 회차와 같은 질문은 내지 않는다(같은 종류라도 다른 지점을 묻는다)
2. 점수가 가장 낮은 두 종류만 꼬리 질문 한 번씩
3. **외울 것 한 장**을 터미널에 낸다(파일로 만들지 않는다). 종류마다 세 줄: 핵심 명사구 3개 · 숫자 1~2개(만든 명령 지금 다시 돌려 같은지) · 대표 `파일:줄`(`sed -n` 원문 앞부분). 그리고 '모를 때의 틀' 2개(`$설명` 4번 모양). 문장으로 풀지 않는다
4. 채점 중 나온 틀린 문서·숫자는 목록만. 고칠지는 사용자가 정한다

마지막 줄: `직접 확인: 점수가 낮은 문항을 화면 없이 다시 써 보기.`
