# 넘기기 전 설명 준비

> 평소에는 따로 커맨드로 두지 않았다. 리뷰·인수인계 전에 머릿속으로 하던 준비(왜 이렇게 했나, 숫자 근거, 약점)를 이번에 스킬로 만든 것이다.

목표: 결과물을 넘긴 뒤 누가 "왜 이렇게 했어요?"라고 물어도, 화면을 보지 않고 내 말로 답할 수 있게 한다.
답안 문장은 대신 쓰지 않는다. 재료(근거 위치와 짧은 명사구)만 준다. 지어내지 않고, 하지 않은 확인을 했다고 쓰지 않는다.

## 읽을 것 (필요한 만큼만)

- `git log --reverse --format='%h %ad %s' --date=format:%H:%M`
- NOTES.md: 요청자 대화 · 결정 · 확인 · 남은 한계
- AGENTS.md: 확정된 규칙 · 확인 안 된 것 · 기각한 대안
- PLAN.md: 다시 정의한 문제 · 완료 조건 · 우선순위
- 핵심 코드: 규칙 주석(`# 규칙 N`)이 있는 곳 위주. 파일 전체를 출력하지 않는다

## 내놓을 것 (터미널에. 파일은 만들지 않는다)

0. **지금 고칠 것** (있으면 맨 위). NOTES·PLAN·AGENTS·제출 문서 전부의 문장(결정 줄의 지표 이름과 그 수의 단위 — 명·건·행 — 가 코드가 세는 것과 같은지 포함) 가운데 코드·커밋·실행 결과로 확인되지 않는 것, NOTES 에서 [추정]·미확인이던 숫자가 제출 문서에 표시 없이 쓰인 곳, 제출 문서의 숫자 가운데 NOTES '진행·확인'과 커밋 메시지에서 `grep` 해 0건이거나 git 이 무시하는 폴더에만 있고 다시 만드는 명령이 없는 것. 문장 위치(파일:줄)와 어긋나는 근거를 한 줄씩. 예: "NOTES 확인: '화면에서 확인함' — 화면 확인 기록 없음". 없으면 "없음".
   - **내가 정하지 않은 이름**: 문서·화면·코드에 쓰인 모듈·상태·화면 이름 가운데 NOTES '결정'에 사용자 출처가 없는 것. `이름 — 쓰인 곳(파일:줄) — 코드 기준 뜻 한 줄`. 사용자가 내 말로 바꾸거나 정의할 때까지 여기 둔다.
   - **제출 문서의 가정·한계 칸**: README 가 정한 제출 문서에 가정·한계·제한 칸이 있으면 비교 기준의 순서·무게 줄을 먼저, 이어서 NOTES '남은 한계' 줄, 1번 답에 미확인이거나 검사기가 계획 코드와 같은 해석·같은 설정 파일로 판정한다고 적은 줄, AGENTS '→ 사용자 결정' 줄, 아직 묻지 않은 `[파악]` 줄마다 `한계 → 제출 문서 파일:줄 / 없음 / 모순` 한 줄씩(하지 않은 확인·빌드 줄 먼저). 제출 문서의 '확인한 것'과 '이견 없음·확인됨'이라고 쓴 줄은 주장 하나씩(한 줄에 이어 쓴 것도 나눠) 요청자 답 시각과 그 답을 받은 내 메시지에 그 항목이 있었는지를 대고, 요청자가 그 주장을 직접 말하지 않았거나 답이 '모름'·'기준 없음'이면 모순.

1. **물을 만한 질문 6~8개.** 종류마다 하나 이상:
   - 무엇이 더 나은 결과인지 판단한 기준과 방법, 더 강한 방법(예: 전체 최적화) 대신 이걸 고른 이유와 포기한 것(첫째·둘째 기준을 바꿔 같은 자료로 돌린 숫자와 그 명령, 기준에 넣은 항목 전부(마지막 항목 포함)와 요청자가 걱정으로 말했지만 기준에서 뺀 지표(뺀 이유의 결정 줄과 함께)의 채택안·비교안 값, 문턱을 넘은 건수로 센 항목은 넘은 것 중 가장 큰 값과 그 묶음만 따로 돌려 얻은 가장 작은 값(하한 — 재지 않았으면 '피할 수 없다'고 쓰지 않는다)도 — 값을 내는 지표가 없는 항목은 '안 잼'. 비교안이 모든 지표에서 나쁘면 맞바꾼 것이 안 보이므로 기준을 바꾼 실행은 빼지 않는다. 못 돌렸으면 미확인)
   - 입력을 받아 결과가 저장되기까지 어느 모듈을 어떤 순서로 거치나 — 단계마다 `파일:줄`, 그때 저장되는 행, 상태 열의 값과 그 값을 바꾸는 줄
   - 규칙을 지킨다는 것을 어떤 경로로 확인하나 — 구현된 확인 장치(검사기의 위반 종류마다 망가뜨린 사본으로 한 번이라도 걸려 본 것과 안 걸려 본 것을 나눠)와, 하지 않았거나 가정으로 남긴 것(검사기가 내 결정을 계획 코드와 같은 해석으로 판정하는 곳 포함)을 나눠서
   - 동시 실행·도중 오류·취소를 **각각 한 줄로**: 남는 저장 행과 그때 화면, 일부러 일으켜 본 명령과 출력이 NOTES '확인'에 있으면 그 시각, 없으면 미확인('동시'는 두 요청을 겹쳐 보낸 것만 친다). 아래는 항목마다 `항목 — 파일:줄 / 해당 없음` 한 줄씩(묶지 않는다):
     - 여러 요청이 저장소 연결·트랜잭션 하나를 같이 쓰는 곳
     - 검사(공개 가능 여부 등)와 저장이 다른 잠금·트랜잭션에 있는 곳
     - 저장이 둘 이상으로 나뉜 곳(커밋되는 줄)과 그 사이에서 끊기면 남는 행을 읽는 화면
     - 상태를 바꾸는 요청이 대상을 id 로 받는지 '그 순간 최신'으로 고르는지(최신이면 그 사이 기준이 바뀔 때 무엇을 돌려주고 응답이 깨지는지)
     - 공개 화면이 공개된 결과 대신 지금 적용된 자료(이름·좌표·이동·확인 시간)나 서버의 '오늘·지금'(시간대·날짜 기본값 포함)으로 다시 계산돼 보이는 곳
   - 조건(문턱·정원·기간·경계에 걸친 대상)을 바꿔 다시 돌리면 어디가 깨질 수 있나 — 아래를 항목마다 한 줄씩, 명령과 숫자로. 돌린 명령은 `checks/` 에 파일로 두고 NOTES '확인'에 `HH:MM 명령 → 출력` 한 줄로 남기고(코드를 고치면 다시 돌려 그 줄을 바꾼다), 그 줄이 없는 숫자는 미확인으로 쓴다:
     - 같은 판정을 두 곳 이상에서 따로 계산하는 곳과 그곳이 읽는 조건(원래 값인지 바꾼 값인지)
     - 기간을 하루로 줄여 돌린 결과와 전체 기간 결과가 그날 몫에서 같은지
     - 운영자가 바꿀 수 있는 조건과 바꿔 넣을 수 있는 자료 파일 종류마다 한 번씩(못 돌린 것은 미확인) 규칙을 못 지킬 만큼 바꿔 돌렸을 때 막히는지·저장·공개되는지, 그 조건을 한 칸씩 풀며(정원 +1 등) 돌려 실패 건수가 늘지 않는지, 실패로 나온 한 건이 정말 갈 곳이 없는지(손으로 한 건)
   - 이 숫자는 어떻게 나왔나 / 요청과 다르게 간 곳은 어디인가 (사용자 결정·요청자 미확인 포함)

   질문마다 아래 모양으로. 칸은 문장이 아니라 짧은 명사구.
   ```
   Q3. 취소 건은 왜 합계에서 아예 뺐나요?
     근거: calc.py:42 (# 규칙 4) · 커밋 a1b2c3d · NOTES 요청자 대화 10:14
     지점: 취소 3건 제외
     왜:   요청자 10:14 "취소는 이용으로 안 본다" / 차감안은 기각(합계가 음수 됨)
     다음: 취소 뒤 재예약 같은 경우는 미확인 → 요청자 확인
   ```
   코드 근거는 함수 이름이 아니라 `파일:줄`로 쓴다. 좌표는 회차마다 새로 `sed -n 'Np' 파일` 로 그 줄을 찍어(앞 회차 좌표를 옮겨 쓰지 않는다) 말과 맞는지 보고, 기준·규칙·저장되는 값(사본·상태)이면 그 값이 쓰이거나 저장되는 호출부까지 따라간다(정의만 있고 안 쓰이면 '근거 없음'). '지점'·'왜' 칸의 숫자와 '한 번에·전부' 같은 단언도 줄이나 명령이 없으면 "근거 없음". 근거가 없는 답은 뼈대에 넣지 않는다.

2. **외울 숫자 5개.** 결과물의 핵심 숫자와 그 숫자를 만든 명령. 명령은 지금 다시 돌려 값이 같은지 확인한 뒤 적는다.
   ```
   - 대상 120건 ← python3 calc.py --count
   ```

3. **전제가 틀린 질문 대비 2~3개.** 다 된 것처럼 보이지만 확인하지 않은 것, 만들지 않은 기능, 요청과 다르게 간 곳을 누가 "이미 된 것"으로 전제하고 물을 때. 질문 예와 바로잡는 첫 문장 틀:
   ```
   - "주말 건도 반영됐죠?" → 실제로는 평일만 구현했습니다. 주말은 '이번엔 안 함'(요청자 10:20 합의)입니다.
   ```

4. **모를 때의 틀.** 확인하지 않은 것을 물으면:
   ```
   그 부분은 확인하지 못했습니다. 확인하려면 ○○를 돌려 △△와 비교하겠습니다.
   ```
   남은 한계 가운데 이 틀로 답해야 할 것을 2~3개 골라 ○○·△△를 채워 둔다.

## 하지 않는 것

- 질문에 대한 완성된 답 문장을 쓰지 않는다(사용자가 자기 말로 말한다)
- 근거 없는 이유를 만들어 넣지 않는다
- 문서를 고치지 않는다. 0번 '지금 고칠 것'은 목록만 내고, 고칠지는 사용자가 정한다

마지막 줄: `직접 확인: 화면을 보지 않고 질문마다 소리 내어 한 문장씩.`
