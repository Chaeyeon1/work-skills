# 요청자 답 → 규칙

입력: 사용자가 붙여 넣은 **요청자와의** 질문과 답. 시각은 **답을 받은 시각** 하나로 NOTES·AGENTS 에 똑같이 쓴다. 없으면 `date +%H:%M` 으로 찍는다(어림하지 않는다).
사용자가 나에게 한 지시("~로 가자", "~해 줘")는 요청자 대화도 규칙도 아니다. 그런 건 NOTES.md '결정'에 `출처: HH:MM 나` 로.

1. **원문 남기기.** NOTES.md '요청자 대화' 아래 `- HH:MM Q: … / A: …`. 요약하지 않는다. 숫자·고유명사는 그대로.
2. **규칙 넣기.** 지킬 규칙이 나왔으면 AGENTS.md '확정된 규칙'에 `N) 규칙 — 출처: HH:MM 요청자`. 번호는 이어서. 작업 순서·전달 방식처럼 코드로 옮길 수 없는 규칙은 끝에 `(코드 아님)` 을 단다.
   - 이미 있는 규칙과 부딪히면 고치지 않는다. 둘 다 보여 주고 사용자에게 묻는다. 사용자가 고르면 진 쪽 규칙 끝에 `(→ 규칙 n 으로 바뀜 HH:MM)` 을 달고, 코드의 `# 규칙` 주석도 이긴 번호로 바꾼다.
   - "보통", "대개", "아마" 로 말한 것은 '확인 안 된 것'으로.
   - 요청자가 말한 숫자가 자료로 잰 숫자와 다르면 규칙으로 넣지 않는다. 두 계산을 나란히(요청자 계산 / 자료로 잰 값과 명령) 보여 주고 사용자에게 묻는다. 요청자에게 보낼 짧은 설명 재료(어디서 갈리는지 한 줄)도 같이 낸다.
3. **빈틈.** (`[파악]` 줄이 이 답으로 풀렸으면 4번처럼 정리한다. 같은 대상의 줄이 이미 있으면 새 줄 대신 그 줄에 경계를 덧붙인다.) 규칙마다 모르는 경계를 '확인 안 된 것'에 **한 줄에 하나씩**, 지금 자료에서 몇 건이 걸리는지 `(지금 N건)` 을 붙여서(셀 수 없으면 `(지금 ?건)`): 경계값(이상/초과), 빈 값, 기간 경계, 예외 대상, 바뀐 버전, 단위, '찾지 못함'과 '정말 없음'의 차이(없으면 그 자체로 위반인지).
4. **'확인 안 된 것' 정리.** 이번 답이 그 줄에 닿았으면 경우에 따라:
   - 풀렸다 → 줄을 지우고 NOTES '결정'에 `- HH:MM '…' → 규칙 N 으로 풀림`
   - 일부만 풀렸다 → 남은 경계만 남게 줄을 고치고 결정에 `→ 일부 풀림(규칙 N)`
   - 요청자가 모른다·기록에서 확인해 달라 → 줄 끝에 `→ 물음 HH:MM, 요청자 모름 — 자료로 잴 것`. '아직 안 물은' 수에서 뺀다. `$구현` 이 잰 값으로 `→ 잼: 값 (커밋)` 을 달아 닫는다. 자료로도 잴 수 없는 것(제출 기한·받는 사람 등)이면 `→ 요청자 모름 · 자료 없음` 으로 닫고 '남은 한계'로 옮긴다
   - 요청자가 판단을 맡겼다("편하신 대로", "알아서") → 줄은 **지우지 말고** 끝에 `→ 요청자가 맡김 HH:MM`. 사용자에게 고르라고 알린다(`$논의` 에서 고르면 그때 정리)
5. **이미 만든 것을 바꾸는 답.** 구현이 끝난 단계에 영향을 주는 규칙이면 PLAN.md '단계'의 마지막 단계 바로 다음(규칙 ↔ 단계 연결 줄보다 위)에 `N. (HH:MM 피드백) 무엇 — 규칙 n — 확인: 명령 → 기대` 를 넣고, 규칙 ↔ 단계 연결에도 새 규칙 번호를 잇는다. 사용자에게 `$구현 N` 을 제안한다.
6. **몇 건에 걸리나.** 셀 수 있으면 명령을 돌려 건수를 센다. 명령도 같이 보여 준다.

끝나면 바꾼 AGENTS·NOTES·PLAN 을 `요구: HH:MM 규칙 N…` 으로 커밋한다.

출력은 다섯 줄 안팎: 추가한 규칙, 확인 안 된 것, 걸리는 건수, **아직 안 물은 `[파악]` 줄 수와 그중 ★**. 그리고 바꾼 섹션(AGENTS '확정된 규칙'·'확인 안 된 것', NOTES '요청자 대화' 마지막 줄)을 `sed -n` 으로 출력해 깨진 곳이 없는지 보여 준다. 문서를 고칠 때 통째 치환 말고 그 줄만 고친다.
요청자가 말하지 않은 숫자·기준은 넣지 않는다.
