# 계획서

README 가 계획 문서 이름·위치를 정했으면 그것을 쓴다. 아니면 `PLAN.md`.

```
# PLAN

## 다시 정의한 문제
요청자가 처음 한 말 → 대화 뒤 내 말. 두세 문장. 누가 언제 무엇을 결정하는 데 쓰는가.

## 완료 조건
| 조건 | 확인 방법(명령 또는 화면) |

## 우선순위
- 먼저: …  (규칙 번호)
- 시간이 남으면: …
- 이번엔 안 함: …  (이유)

## 단계
1. 무엇 — 확인: `명령` → 기대 결과
```

- 완료 조건은 숫자나 눈으로 볼 수 있는 행동으로. "잘 동작한다" 는 쓰지 않는다.
- 확인 명령은 결과의 내용을 세거나 비교해야 한다. 파일이 있는지(`test -f`)·오류 없이 끝났는지만 보는 확인은 쓰지 않는다.
  예: "빨간 칸 수 = 판정 이탈 수", "메일 속 대상 = 이탈 대상 (`diff` 출력 없음)", "손계산한 한 건 = 출력의 그 줄"
- 정확도·기준값을 재는 단계가 있으면, 기준을 정할 때 볼 사례와 잴 때만 쓸 사례를 계획에서 미리 나눈다.
- 단계는 한 번에 끝낼 크기로 4~6개. 판정·계산 먼저, 화면·꾸밈은 나중.
- 확정된 규칙마다 어느 단계에서 다루는지 번호로 잇는다. 이어지지 않은 규칙은 표 아래에.
- 근거 없는 내용은 [추정].

PLAN 을 쓴 뒤 AGENTS.md '목표'를 다시 정의한 문제와 완료 조건으로 채운다(비어 있으면 `$구현` 이 멈춘다).

쓰고 나면 멈춘다. 마지막 줄: `직접 확인: '다시 정의한 문제'를 내 말로 고치고, 우선순위가 요청자와 합의한 순서인지.`
