# 결과 보고 (넘기기 전)

요청자가 모르는 동작이 하나도 남지 않게 한다. 말로 "됐다"가 아니라 실행 결과로.

1. **기능·케이스 뽑기.** 기억 말고 코드와 커밋(`git log --oneline`, `git diff <첫 커밋>..HEAD --stat`)에서 뽑는다: 분기, 기본값, 막는 조건, 오류 문구, 빼는 경우.
2. **수정 전/후.** 작업 트리가 깨끗할 때만(아니면 먼저 커밋). 가장 중요한 규칙 하나를 잠시 끄고 확인 명령을 돌려 결과가 달라지는지 본다. `git checkout -- <파일>` 로 원복하고 `git status` 가 깨끗한지 보여 준다. 달라지지 않으면 그 확인은 아무것도 확인하지 않은 것이라고 적는다.
3. **실행 방법 따라 하기.** README 의 실행 방법을 처음 보는 사람처럼 위에서부터 그대로 실행한다. 막히면 README 를 고친다.
4. **README 넘김 내용.** 없으면 쓰고, 있으면 고친다:
   - 무엇을 위한 것인지 한두 줄 / 실행 방법 / 기능·케이스 표 / 규칙별 확인 결과(규칙 번호 → 명령 → 결과) / 남은 한계(🔴🟠🟡)
5. **문서와 실제가 다른 곳.** NOTES·README·PLAN 의 문장 중 코드·커밋·실행 결과로 확인되지 않는 것을 찾아 고치거나 [추정] 을 단다. 사용자가 하지 않은 확인을 적지 않는다.

마지막: 바꾼 파일과, 사용자가 화면에서 직접 볼 것(`직접 확인:`).
