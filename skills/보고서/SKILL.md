# 결과 보고 (넘기기 전)

요청자가 모르는 동작이 하나도 남지 않게 한다. 말로 "됐다"가 아니라 실행 결과로.

1. **기능·케이스 뽑기.** 기억 말고 코드와 커밋(`git log --oneline`, `git diff <첫 커밋>..HEAD --stat`)에서 뽑는다: 분기, 기본값, 막는 조건, 오류 문구, 빼는 경우. 이 가운데 **규칙 근거 없이** 경고 없이 값을 빼거나 판정에서 빠지거나, 규칙을 못 지킨 결과를 '확인 필요' 없이 만들어 내는(검사기만 잡는) 경우가 '확인 안 된 것'에 없으면(규칙대로 뺀 것은 뺀 줄 수가 결과물에 보이는지만 본다), 줄을 넣고 PLAN 새 단계로 제안해 `$구현` 으로 처리한다(남은 한계로만 넘기지 않는다).
2. **넘김 내용.** 요청 문서가 안내 문서를 정했으면 그 파일에(요청 문서는 고치지 않는다), 아니면 README 에. 없으면 쓰고, 있으면 고친다:
   - 무엇을 위한 것인지 한두 줄 / 실행 방법 / 기능·케이스 표(확인 칸과 본문에 적은 명령은 그 결과 값을 같은 데이터셋·조건·환경변수로 내는 것만 — 새 셸에서 적힌 그대로 쳐서 같은 값인지 본다) / 규칙별 확인 결과(요청자 규칙 번호와 내가 정한 것(결정 HH:MM)을 다른 줄로 → 명령 → 결과) / 남은 한계([높음]·[중간]·[낮음])
   - 파이프(`|`)가 든 명령은 표 칸에 넣지 말고 표 아래 코드 블록에 둔다(표 칸에서 `\|` 로 깨져 그대로 따라 칠 수 없다)
3. **실행 방법 따라 하기.** 방금 쓴 실행 방법을 처음 보는 사람처럼 위에서부터, 적은 경로마다 그대로 실행한다(못 돌린 경로는 [미확인]). 막히면 안내 문서를 고친다. 따라 하기가 막힘 없이 끝난 뒤, 4번 전에 안내 문서를 `보고서: 넘김 내용` 으로 커밋한다(4번은 깨끗한 트리에서 시작해야 한다).
4. **수정 전/후.** 작업 트리가 깨끗할 때만(아니면 먼저 커밋. 결과물을 다시 만들어 생긴 변경도 되돌리고 시작). 가장 중요한 규칙 하나를 잠시 끄고 결과를 `.verify/` 같은 git 이 무시하는 폴더에 만든 뒤, **완료 조건의 확인마다** 달라졌는지 표로 적는다(`| 확인 | 켰을 때 | 껐을 때 |`, NOTES '확인' 아래). 숫자 합계만 보지 말고 그 규칙이 걸리는 행을 직접 비교한다. 끝나면 `git checkout -- .` 로 되돌리고 `git status` 가 깨끗한지 보여 준다. 어느 확인으로도 달라지지 않으면 그 규칙이 걸리는 경우를 담은 사본을 만들어 다시 비교하고, 그래도 같을 때만 '남은 한계'에 적는다.
5. **문서와 실제가 다른 곳.** NOTES·PLAN·AGENTS·제출 문서·바뀐 코드의 설명 주석 전부의 문장(`(지금 N건)`·남은 한계 줄의 숫자와 'a~b' 범위는 마지막 결과로 그 줄이 걸리는 대상 집합(기간·필수 여부를 거른 뒤)에서 다시 세고 숫자를 낸 조건(기간·설정·데이터셋)이 문장에 붙어 있는지 보며, 여러 대상을 묶은 줄은 대상마다 다시 잰다) 중 코드·커밋·실행 결과로 확인되지 않는 것, '전부·모두·마다·위반 0'처럼(그 말이 걸린 대상 집합을 코드에서 열어 맞춘다) 코드 조건이나 검사 범위보다 넓은 말을 찾아 고치거나 범위·[추정] 을 단다. 한 줄(예시 명령 포함)을 고치면 같은 값이나 그 줄을 가리키는 말('같은 기간'·'위 명령')을 적은 다른 줄을 `grep` 으로 찾아, 고친 명령을 다시 돌린 값으로 같은 커밋에서 고친다. 사용자가 하지 않은 확인을 적지 않는다.
6. **커밋.** 4·5번에서 바뀐 NOTES·안내 문서를 `보고서: 끄고 비교 — 확인: …` 으로 커밋한다.

7. **보고 화면.** 기계로 뽑고, 쉬운 말로 채우고, 그린다.
   - `python3 .agents/skills/보고서/scripts/report_html.py draft` (없으면 `~/.agents/skills/…`) → `.verify/report.json` 초안. 바뀐 파일·바뀐 줄의 분기·checks 이름·규칙·요청자 미확인 결정·남은 한계·커밋이 `_` 칸에 들어간다.
   - 빈 칸을 **요청자가 부르는 말로**(코드 이름은 괄호) 채운다. 맨 앞 네 칸이 핵심이다:
     ① `features` 기능 목록 — 무엇을 할 수 있게 됐나·언제 보이나. 요청자가 처음 듣는 기능이 없게
     ② `flow` 동작 원리 — 입력 파일·칸 → 판단 규칙(근거 `파일:줄` 과 코드 원문 한 줄) → 출력 칸·화면 자리
     ③ `cases` 케이스 표 — 입력 조건(경계·빈 값·처음 보는 값·중복·기간 밖) · 결과 · 확인 방법(그 입력을 실제로 담은 사본·명령만, 일부 기간·대상만 돌렸으면 그 범위까지, git 에 없으면 다시 만드는 명령까지). 확인 못 한 것은 지우지 말고 `미확인`
     ④ `diffs` 요청과 다른 점 — 무엇이·왜·누가 정했나(`요청자 HH:MM` / `사용자 결정 HH:MM (요청자 미확인)`)·대기 중인 질문
     그리고 `summary`(요약 세 줄, 숫자는 실제 출력에서) · `files`(파일마다 무엇이 달라졌나 한 줄) · `before_after`(4번 끄고 비교: 수정 전/후 결과 줄이나 표, 어떻게 껐고 되돌렸나) · `view`(보는 순서: PORT·URL·무엇을 누르나, 자리표시자 없이).
   - 인자 없이 다시 돌려 `view/report.html` 을 그린다. 그릴 때마다 누락을 대조한다(바뀐 파일·checks 이름·확정된 규칙·미확인 결정이 각각 파일 목록·케이스 표·동작 원리/케이스·다른 점에 다 있나). **'누락 N' 이 0 이 될 때까지** 채운다.
   - 보는 법: 새 터미널 `python3 -m http.server 8090 --bind 0.0.0.0` → Browser 탭 PORT 8090, URL `/view/report.html`. 요청자에게 결과를 보여 줄 때도 이 화면을 쓴다. 띄운 서버는 PID 를 적어 두고 끝나면 그 PID 로만 끈다(이름으로 찾아 끄지 않는다). 포트가 쓰이고 있으면 다른 포트로 띄운다.
   - (평소에는 수정 전/후를 **같은 조건에서 찍은 실제 화면 캡처**로 넣는다 — 제보 원본 · 수정 전 · 수정 후 세 장. 캡처를 쓸 수 없는 환경, 예를 들어 캡처 단축키를 막아 둔 원격 작업 환경에서는 아래처럼 실제 출력 발췌로 대신한다. 숫자로 증명한다는 원칙은 같다.)
   - 수정 전/후 칸은 **실제 출력 발췌**로 채운다: 끄고 비교에서 달라진 행의 표(`table`), 결과 줄(`lines`), 화면이면 그 부분의 HTML 원문 몇 줄. 사람 손으로 화면을 캡처하지 않는다(캡처 단축키를 막아 둔 환경이 있다). 이미지가 꼭 필요하고 헤드리스 브라우저가 이미 있으면 에이전트가 찍어 `view/img/` 에 두고 `"img": "img/파일.png"` 로 넣는다(`.verify/` 에 두면 커밋되지 않아 깨진다).
   - `view/report.html` 은 커밋한다(`보고서: 보고 화면`). 그 뒤 코드·NOTES·제출 문서가 바뀌면 넘기기 전에 인자 없이 다시 그려 같은 커밋에 넣는다.

마지막: 바꾼 파일과, 사용자가 화면에서 직접 볼 것(`직접 확인:`), 요청자에게 보여 줄 요약 세 줄과, 그 밑에 요청자 미확인 사용자 결정을 모두 "제가 정한 것"으로(대상·기간을 바꾸는 것 먼저). 보내기 전에 AGENTS 에서 `(요청자 미확인)` 이 달렸고 `이견 없음`·`맡김` 이 없는 줄 수와 메시지 번호 수를 나란히 적는다. 보내기 전에 `$설명` ⑤ 재료의 조건 바꿔 돌리기를 먼저 해 둔다(뒤에 버그가 나오면 보낸 숫자가 낡는다). 요약의 숫자·사례는 방금 돌린 실제 출력에서 옮기고, 보낸 메시지의 숫자가 뒤에 바뀌면 바뀐 값과 이유 한 줄을 정정 메시지로 낸다.
