# 요청 파악 (만들지 않는다)

코드는 만들지 않는다. 문서는 둘만 건드린다:
- `NOTES.md` 가 없으면 아래 뼈대로 만들고 '진행' 첫 줄에 지금 시각(`date +%H:%M`)을 적는다.
- 아래 3·4번에서 찾은 것 중 아직 답이 없는 것을 AGENTS.md '확인 안 된 것'에 **한 줄에 하나씩** `- [파악] 무엇 — 물어볼 것` 으로 넣는다. 기본 질문 둘, 먼저 물을 3개, 시점 말 줄에는 `★`. 짚고 넘어간 것이 대화 중에 사라지지 않게 하기 위해서다.

```
# NOTES
## 요청자 대화
## 진행
- HH:MM 시작
## 결정
## 확인
## 남은 한계
```

## 순서

1. **요구 사항.** README·요청 문서에서 산출물·파일 이름·위치·형식·실행 방법·하면 안 되는 것. 없으면 "지정 없음".
2. **자료 훑기.** 파일마다 크기부터(`wc -l`). 50줄 이하는 통째로 읽고, 큰 파일은 앞부분(`head`)과 필요한 곳만. 이름이 비슷한 파일(버전·변경본·사본)은 `diff` 로 서로 비교한다. 표 자료는 열 이름, 값의 종류, 빈칸, 중복, 단위, 시각 형식, 비고란. 큰 파일을 통째로 읽지 않는다.
3. **이상한 점 표.** `| # | 어디(파일:줄 또는 열) | 본 것 | 물어볼 것 | 답에 따라 바뀌는 것 |`
   - 자료끼리, 요청 문서와 자료가 서로 다른 말을 하는 곳을 맨 위에
   - 이름이 다른 파일(변경본, 예전 버전, 메모), 끝났거나 진행 중인 건, 같은 대상이 두 번 나오는 곳
   - 물어볼 것은 대상 하나 + 구체 상황 + 열린 질문. 예: "P-03 은 표와 메모의 종료일이 다른데, 어느 쪽을 기준으로 보시나요?"
   - 끝이 "~하나요?", "~할까요?", "~인가요?" 로 예/아니오가 나오는 문장은 "어떻게 / 어느 쪽 / 언제부터 / 어떤 경우에" 로 고쳐 쓴다.
     나쁨: "변경 합의서를 우선 적용하나요?" → 좋음: "원 계약과 합의서 내용이 다를 때 어느 쪽 기준으로 보세요?"
   - 답에 따라 바뀌는 것은 건수·판정이 어떻게 달라지는지 한 줄
4. **정해지지 않은 말.** "적절히", "주요", "정리" 처럼 기준·기간·대상이 빠진 말. 물어볼 것을 단다. "감사 전", "연말", "다음 회의 때" 같은 시점 말은 **날짜로** 묻는다(기준일 뒤에 생기는 일 — 곧 만료·곧 마감 — 이 거기서 드러난다).
5. **먼저 물을 것.** 기본 질문 둘은 언제나 ★ 맨 위에 둔다: "이 결과를 누가 언제 어디서 쓰나", "지금은 이 일을 어떻게 하고 어디서 시간이 드나"(다시 정의한 문제가 여기서 나온다). 그 밑에 결과를 가장 크게 뒤집는 것 3개를 ★.

자료에서 확인되는 사실은 묻지 않고 확인해서 적는다. "뭘 만들면 되나요" 같은 넓은 질문, 해법이 들어간 질문은 넣지 않는다. 요청자가 지금 어떻게 하는지 말하게 묻는다.

마지막 줄: `직접 확인: ★ 3개부터 내 말로 하나씩 물어보기. 꼬리 질문은 답을 듣고. 합의 확인 전에 AGENTS '확인 안 된 것'에 남은 [파악] 줄을 본다.`
