# 함정 장부 (고치지 않는다)

> 평소에는 마무리 전에 "처음에 이상하다고 적어 둔 것들, 다 처리했나"를 메모를 넘기며 하나씩 지웠다. 그걸 표로 만든다.

`$검사` 는 규칙이 코드에 들어갔는지를 본다. 이건 **처음 찾은 후보부터** 끝까지 따라간다 — 규칙이 되지 못하고 사라진 후보도 잡기 위해.

## 1. 모으기 (빠짐없이)
- NOTES 의 `[파악]` 줄 전부(풀린 줄도)
- 요청 문서(README)의 운영 규칙·요구사항 문장마다 한 줄(한 문장에 조건이 둘이면 둘로)
- AGENTS '확정된 규칙' · '확인 안 된 것' 줄 전부
출처마다 `grep -c` 로 센 수를 먼저 찍고, 표의 행 수가 그 합과 같은지 맞춘다(같은 내용이면 한 행에 출처를 함께 적되 수는 따로 센다).

## 2. 줄마다 따라가기
- **코드**: 그 내용을 지키는 줄 `파일:줄`(`sed -n` 원문 앞부분). `# 규칙 N` 이 없으면 `grep -n` 으로 찾고, 정의만 있고 안 쓰이면 '코드 없음'
- **걸려 본 확인**: 망가뜨린 사본·조건을 바꾼 실행·고치기 전에 실패했던 확인 가운데 이 줄을 실제로 걸리게 한 것 — NOTES '확인' 시각과 명령. 검사기 규칙 이름만 있고 걸려 본 적이 없으면 '검사만'
- **요청자**: 확인한 시각 / 답 없음 / 요청자 결정 아님 / 안 물음
- **상태** 하나:
  `닫힘`(코드 + 걸려 본 확인) · `코드만` · `검사만` · `코드 없음` · `물어봄·답 없음` · `안 물음` · `일부러 안 함`(NOTES 결정 시각) · `해당 없음`(이유와 0을 찍은 명령)

## 3. 유형 훑기 (자료와 코드에서 다시 본다)
아래마다 자료에 해당하는지 명령으로 세고, 해당하면 표의 어느 행이 맡는지 잇는다. 맡는 행이 없으면 새 행으로 넣는다(상태는 대개 `안 물음`이나 `코드 없음`). 해당이 없으면 `0건 — 명령`.
- 자정·기간 경계를 넘는 묶음의 날짜(묶는 날짜와 실제 시각의 날짜가 다른 항목)
- 기록·실적을 수요나 대상으로 씀(기록에 없는 대상이 빠짐)
- 행마다 반복된 값을 더함(묶음 값이 행 수만큼 부풀려짐)
- 방향마다 다른 값(A→B ≠ B→A)을 한쪽으로만 씀
- 체감·선호 문턱을 지킬 상한으로 둠 — 꼭 지키면 갈 곳 없는 건수
- 두 파일이 같은 것을 다르게 말함(기본값 vs 그날 값, 목록 vs 기록) — 믿은 쪽과 결정 줄
- 묻지 않으면 모르는 운영 규칙(혼자 하면 안 되는 것, 한꺼번에 비우면 안 되는 것, 쓸 수 없는 때)
- 조건 두 개가 함께 걸려 고를 곳이 거의 없는 대상 — 그 대상 수와 고를 수 있는 곳 수
- 정원·상한 때문에 빠지는 대상이 조용히 통과(확인 필요로 남는지)
- 공개 범위(작업 중 결과가 보이면 안 되는 역할)
- 새 자료를 적용했는데 저장된 설정·옛 결과가 남음
- 만드는 사람이 정한 것을 요청자 결정처럼 씀
- 요청 범위 밖 기능을 만듦

## 내놓을 것 (터미널에. 파일은 만들지 않는다)
```
출처별 수: [파악] n · 요청 문서 n · 확정된 규칙 n · 확인 안 된 것 n · 유형 훑기에서 새로 n → 표 N행
| # | 함정 (출처) | 코드 | 걸려 본 확인 | 요청자 | 상태 |
상태별 수: 닫힘 n · 코드만 n · …
```
이어서 **안 닫힌 것, 고칠 순서로**:
1. `안 물음` — 요청자에게 보낼 질문 한 줄씩(`보낼 말:` 규칙대로)
2. `코드 없음` — PLAN 새 단계로 넣자는 제안
3. `코드만`·`검사만` — 걸리게 만들 사본이나 조건과 그 명령(돌리지 않고 명령만)
4. `물어봄·답 없음` — 제출 문서의 가정·한계 칸에 있는지(`파일:줄` / 없음)

근거 없는 '닫힘' 은 쓰지 않는다. 확인 명령의 출력을 지금 다시 보지 않은 줄은 `코드만` 으로 둔다.
고칠지는 사용자가 정한다. 코드는 `$구현`, 질문은 `$요구` 로 넘긴다.

마지막 줄: `직접 확인: '안 물음' 줄부터 내 말로 하나씩 보내기.`
