# 한 단계 구현

1. AGENTS.md 와 PLAN.md 의 그 단계만 읽는다. 다른 단계는 하지 않는다. 그 단계의 확인 명령에 [추정] 이 있으면 실제로 만든 형식으로 고친다.
2. 구현 전에 할 일과 건드릴 파일을 두세 줄로. 방법이 둘 이상이면 멈추고 `$논의` 를 제안한다. 이 단계가 AGENTS '확인 안 된 것' 줄을 한쪽으로 정해야 하면(처음 보는 값을 어떻게 볼지, 빈 값을 어디에 넣을지 등) 구현 전에 그 줄을 보여 주고 멈춰서 묻는다.
3. 구현한다. 판정·계산은 코드로. 규칙을 옮긴 곳에 `# 규칙 N`.
4. 단계의 확인 명령을 실행하고 출력을 그대로 보여 준다. 출력이 비었거나 경고·오류가 섞였으면 확인이 돌지 않은 것이다('없음' 확인은 `grep -c` 처럼 0을 찍게 하고, 있어야 할 곳의 대조를 같이). 기대와 다르면 원인을 한 번 확인하고 고친 뒤 같은 명령을 다시.
   화면을 만드는 단계면 숫자 확인과 별도로 화면을 열어 보라고 `직접 확인:` 에 적는다. 숫자가 맞아도 화면에서 오해할 표시가 있을 수 있다.
5. 한 건을 손으로 맞춰 볼 수 있게 입력 한 줄과 기대 출력 한 줄을 골라 `직접 확인:` 으로 칠 명령을 준다.
6. NOTES.md '진행' 제목 아래에 `- HH:MM N단계 · 한 것 · 확인: 명령 → 결과` 한 줄. 시각은 `date +%H:%M` 에서. 커밋 해시는 적지 않는다(같은 커밋에 넣기 위해).
7. 코드·NOTES·이 단계에서 바뀐 AGENTS/PLAN 을 한 커밋으로: `N단계: 무엇 — 확인: 명령 → 결과`. 샌드박스가 `.git` 쓰기를 막으면 승인을 요청한다. 그래도 안 되면 사용자가 칠 커밋 명령을 그대로 준다.
8. 사용자가 `직접 확인` 결과를 알려 주면 NOTES '확인'에 `- HH:MM 직접: 명령 → 결과` 한 줄을 넣고 다음 커밋에 함께 넣는다.
9. 멈춘다. 다음 단계는 사용자가 부를 때.

서버를 띄우는 단계면 0.0.0.0 에 바인딩하고, 띄운 터미널은 그대로 두라고 알려 준다. 포트와 경로를 `직접 확인:` 에.
