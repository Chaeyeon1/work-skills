# 작업 기록

> 평소에는 /기록 으로 날짜별 일지에 논의·의사결정·트러블슈팅·배운 것을 시간과 함께 남기고, /commit 이 기록 → 기능 문서화 → 커밋을 한 흐름으로 돌린다(커밋 전에 사용자 확인). 여기서는 일지 대신 NOTES.md 의 제목(진행·결정·확인·남은 한계) 아래에 남기고 마디마다 커밋한다.

README 가 기록 문서 이름을 정했으면 그 파일에. 아니면 `NOTES.md`. 덧붙이기만 하고 지우지 않는다. 파일 끝에 붙이지 말고 알맞은 `##` 제목(진행 · 결정 · 확인 · 남은 한계) 아래에 넣는다.
시각은 지금 시각(`date +%H:%M`)이나 커밋 시각(`git log`)에서 가져온다. 어림해서 적지 않는다. 틀린 기록은 지우지 말고 `(정정 HH:MM: …)` 을 달고, 같은 숫자·이유·순서를 적은 다른 줄(AGENTS '기각한 대안'·view·코드 주석·`checks/` 표시 이름 포함)을 항목 이름으로 `grep` 해 찾아 같은 커밋에서 고친다.

줄 종류마다 해당 `##` 제목 아래에 따로 넣는다:

```
## 진행        - HH:MM 무엇을 했나 / 트러블슈팅: 증상 → 원인(잰 것) → 고친 것 → 다시 확인한 결과 → 그 증상을 적은 안내 문서 줄 고침/없음
## 결정        - HH:MM 무엇을 / 왜(출처: 요청자 HH:MM, 커밋, 파일:줄) / 기각한 것과 이유
## 확인        - HH:MM 명령 → 결과 (사용자가 직접 본 것은 '직접:')
## 남은 한계   - [높음]·[중간]·[낮음] 무엇이 틀릴 수 있나 → 어떻게 확인하나(명령. 할 일을 적었으면 그것을 한 코드 `파일:줄`, 없으면 '안 함')
```

여러 줄을 한꺼번에 남길 땐 각 제목 아래에 `### [HH:MM] 한 줄 제목` 블록을 둘 수 있다.

쓴 뒤 `grep -c '^## ' NOTES.md` 가 쓰기 전과 같은지 보고(제목이 지워지면 그 아래 줄이 엉뚱한 곳에 붙는다) `기록: 한 줄 제목` 으로 커밋한다. 그리고 터미널에 짧게:
- **설명해야 할 지점 3개.** 이 결과물에서 누가 "왜 이렇게 했어요?" 라고 물을 곳. 짧은 명사구로.
- **약점 3개.** 틀릴 수 있는 곳 → 그러면 무슨 일이 → 어떻게 확인할지.

문장을 대신 다듬어 주지 않는다. 사용자가 자기 말로 말할 수 있게 재료만.
