# work-skills

## 에이전트용 설치 (사용자가 "work-skills 깔아 줘"라고 하면)

작업 폴더(지금 열린 폴더) 맨 위에서 그대로 한다:

```bash
[ -d ~/work-skills ] && git -C ~/work-skills pull --ff-only || git clone https://github.com/Chaeyeon1/work-skills ~/work-skills
bash ~/work-skills/install.sh --project .
ls .agents/skills && ls AGENTS.md AGENTS.kit.md 2>/dev/null
```

- 스킬은 작업 폴더의 `.agents/skills/` 에 깐다(`--project`). 제출물에 포함되게 하기 위해서다. 홈(`~/.agents`)에만 깔지 않는다
- 작업 폴더에 `AGENTS.md` 가 이미 있으면 덮지 않고 `AGENTS.kit.md` 로 둔다 → 그 경우 "AGENTS.kit.md 규칙도 따른다"를 기존 AGENTS.md 맨 아래에 한 줄 붙일지 사용자에게 묻는다
- 끝나면 스킬 목록(13개)과 AGENTS.md 위치를 보여 주고, 사용자에게 `/skills` 에서 보이는지 확인하라고 한 줄로 알린다. 다른 파일은 만들거나 고치지 않는다

현업 요청을 받아 AI 코딩 에이전트(Codex)와 작은 도구를 만들 때 쓰는 개인 작업 스킬.
평소 Claude Code 커맨드로 쓰던 흐름(논의 · 계획서 · 구현 · 검사 · 보고서 · 기록)을 Codex 스킬로 옮기고, 요청자와 요구를 맞추는 단계(파악 · 요구)를 더했다.

## 생각

- **AI 는 후보를, 사람은 선택을.** 자료의 이상한 점마다 근거(파일:줄)와 물어볼 것을 AI 가 뽑는다. 무엇을 물을지, 어느 안으로 갈지는 사람이 고른다.
- **들은 규칙은 바로 AGENTS.md 로.** 요청자에게 들은 규칙이 지시에 안 들어가는 게 가장 흔한 실수다. 규칙마다 출처 시각을 붙이고, 코드에는 `# 규칙 N` 주석으로 잇는다.
- **분석과 구현을 나눈다.** 파악 · 논의 · 검사는 코드를 고치지 않는다.
- **한 번에 한 단계.** 단계마다 확인 명령 → 커밋 → 기록. 에이전트의 "완료"는 가설이다.
- **원인과 숫자는 재서 말한다.** 재지 않은 것은 [추정]. 하지 않은 확인은 적지 않는다.
- **작게.** 문서 셋(AGENTS · PLAN · NOTES)으로 끝낸다.

## 설치

```bash
git clone https://github.com/Chaeyeon1/work-skills ~/work-skills
bash ~/work-skills/install.sh .            # 스킬은 ~/.agents/skills, AGENTS.md 는 지금 폴더
bash ~/work-skills/install.sh --project .  # 스킬도 지금 폴더 .agents/skills 에
```

`codex` 를 (다시) 켜고 `/skills` 에서 확인한다.
안 보이면: `~/work-skills/skills/파악/SKILL.md 를 읽고 그대로 해 줘`.

## 흐름

| 단계 | 사람 | 에이전트 |
|---|---|---|
| 요청 받음 | 요청 문서 읽기 | `$파악` |
| 요구 맞추기 | 3개 골라 내 말로 하나씩 묻고, 꼬리 질문은 답을 듣고 | `$요구 (질문과 답, 시각)` |
| 요구 맞추는 동안 (다른 터미널, 원하면) | 과제 한 장 읽기 | `$뼈대 환경 모드` · `$설명 과제` → view/brief.html |
| 방향 | 비교표를 보고 고르기 | `$논의 (주제)` |
| 고를 것이 쌓이면 | 그림을 보고 고르고 답 복사 → 붙여 넣기 | `$질문` → view/questions.html |
| 합의 | 요청자에게 이해한 문제와 우선순위 확인 | `$계획서` → view/plan.html 로 대조, 내 말로 고치기 |
| 웹 서비스면 | 틀을 깔고 자료 모양만 채우기 (환경 모드로 이미 깔았으면 계산부터) | `$뼈대` |
| 만들기 | `직접 확인:` 명령을 내가 친다 | `$구현 1`, `$구현 2` … |
| 점검 | 빠진 규칙 고치기 | `$검사` |
| 함정 대조 | 처음 찾은 후보가 다 닫혔는지 표로 보고, 안 물은 것 보내기 | `$함정` |
| 넘기기 | 요청자에게 결과 보여 주기 | `$보고서` → view/report.html |
| 핵심이 처음 돈 뒤 · 넘기기 전 | 물을 만한 질문에 내 말로 답해 보기 | `$설명` |
| 넘기기 전 연습 | 질문에 내 말로 답을 쓰고 채점받기(여러 번) | `$문답` · `$문답 실전` |
| 마디마다 | 내 말로 결정 이유 덧붙이기 | `$기록` |

## 스킬

| 스킬 | 하는 일 | 바꾸는 파일 |
|---|---|---|
| `파악` | 요구 사항, 자료의 이상한 점 + 물어볼 것 + 먼저 물을 3개 | NOTES.md 뼈대만 |
| `요구` | 요청자 답 → 원문 기록, 규칙(출처 시각), 빈틈, 걸리는 건수 | NOTES.md, AGENTS.md |
| `논의` | 접근법 비교표와 추천. 고르면 결정·기각 기록 | NOTES.md, AGENTS.md |
| `질문` | 고를 것마다 자료 몇 줄과 선택지별 결과, 추천 미리 선택, 메모, 답 복사 | view/questions.html, AGENTS.md, NOTES.md |
| `계획서` | 다시 정의한 문제, 완료 조건, 우선순위, 단계별 확인 명령, 예시 한 건 + 대조 그림 | PLAN.md, view/plan.html |
| `뼈대` | 서버·DB·로그인·역할별 화면·내보내기·독립 검사기·smoke 틀을 깔고 채울 곳 안내 | app/ · static/ · checks/ · Dockerfile · HOW_TO_RUN.md |
| `구현 N` | 한 단계 → 확인 명령 → 커밋 → 기록 → 멈춤 | 코드, NOTES.md |
| `검사` | 점검 스크립트, 규칙 ↔ 코드 대조, 사용자가 안 정한 결정 찾기 | 없음 |
| `함정` | `[파악]`·요청 문서 규칙·확인 안 된 것을 한 줄씩 코드·걸려 본 확인·요청자 답과 대조, 자주 나오는 함정 유형 훑기, 안 닫힌 것 순서 | 없음 |
| `보고서` | 기능·케이스 추출, 잠시 끄고 비교 후 원복, 실행 방법 따라 하기, 넘김 내용 | README.md |
| `설명` | `과제`: 코드 전 과제 한 장(만들 것·자료 지도·흐름·규칙·함정·먼저 물을 것) → view/brief.html. 그냥: 물을 만한 질문(선택과 포기 · 모듈 순서 · 검증과 가정 · 실패·동시 실행 · 조건 바꿀 때) 재료, 내가 정하지 않은 이름 | view/explain.html (한 장 그림) |
| `문답` | 실제 코드·기록을 근거로 질문을 하나씩 내고, 쓴 답을 맞음·틀림·근거 없음·빠짐으로 채점, 꼬리 질문 | 없음 |
| `기록` | 결정·트러블슈팅·확인을 시간과 함께, 설명할 지점과 약점 | NOTES.md |

점검 스크립트만 따로: `bash ~/work-skills/skills/검사/scripts/check.sh`

화면 보기: 작업 폴더에서 `python3 -m http.server 8090 --bind 0.0.0.0` → 미리보기(Browser) PORT 8090, URL `/view/plan.html` · `/view/questions.html` · `/view/report.html` · `/view/explain.html`

NOTES.md 를 에디터에 열어 둔 채 에이전트가 쓰면 저장 충돌이 날 수 있다. 에이전트가 쓴 뒤 다시 불러오고 내 문장을 더한다.

## 평소 하던 방식과 이 스킬

평소에는 Claude Code 커맨드로 같은 흐름을 돌린다. 이 키트는 그 흐름을 Codex 스킬로 옮기면서, 작은 작업 폴더 하나와 요청자 한 명을 전제로 크기를 줄였다. 각 SKILL.md 맨 위에 '평소에는'을 한 줄씩 적어 두었다.

| 스킬 | 평소 | 여기서 달라진 점 |
|---|---|---|
| 파악 | 기능 문서에 기획·맥락부터 쌓는다 | 요청자에게 물을 것을 자료 근거와 함께 뽑는 단계를 더함 |
| 요구 | 맥락은 기능 문서, 규칙은 규칙 문서 한 곳(SSOT)에 출처와 함께 | 규칙 문서 = AGENTS.md, 답마다 출처 시각과 모르는 경계 |
| 논의 | 분석만. 비슷한 코드·프로젝트 규칙·업계 사례를 세 갈래로 조사해 비교표와 추천 | 자료·확정된 규칙 기준 비교, 고른 것과 기각한 것을 기록 |
| 질문 | 채팅 대신 그림으로 고르는 HTML(미니 화면, 추천 미리 선택, 메모, 답 복사) | 미니 화면 대신 자료 몇 줄과 선택지별 결과 숫자 |
| 계획서 | 고치기 전 HTML 한 장: 실측 원인, 지금/고친 뒤 캡처, 원인 그림, 코드 방향 | PLAN.md + view/plan.html 로 내 이해와 에이전트 이해를 대조 |
| 구현 | 분해 분석 → 규칙 문서 강제 읽기 → 역할별 에이전트, 시작 전 확인 | PLAN 한 단계씩, 확인 명령 → 기록 → 커밋 → 멈춤 |
| 검사 | 바뀐 파일을 규칙 문서 기준으로, 고치지 않고 근거와 함께 | 확정된 규칙 ↔ 코드 주석 대조 + 점검 스크립트 |
| 보고서 | 같은 조건의 실제 화면 캡처(제보 원본·수정 전·수정 후), 확인 링크, 기능·동작 원리·케이스 표, 누락 대조 | 캡처를 못 쓰는 환경에선 실제 출력 발췌로 수정 전/후 |
| 기록 | 날짜별 일지 + /commit 이 기록 → 문서화 → 커밋 | NOTES.md 제목별, 마디마다 커밋 |
| 설명 | (따로 없음) | 넘기기 전 리뷰 대비를 새로 스킬로 |

평소 흐름에는 있지만 여기엔 넣지 않은 것: 설계도(값을 바꿔 보며 결과가 갈리는 화면과 데이터 가공 흐름), 구조도(다 만든 코드를 거꾸로 읽어 구조·데이터 흐름을 그림으로), 브라우저 회귀 QA.
